# LearnMate AI — Voice-Based Intelligent Learning Assistant

LearnMate AI is a web application that lets students learn through an AI tutor, ask questions about their own uploaded study material (PDF), speak questions using their voice, listen to spoken answers, generate quizzes from their documents, and track their quiz performance over time. The app is built on **TanStack Start** (a full‑stack React framework) with **Supabase** as the database, auth, and file storage backend.

> This document was generated by inspecting the actual project source code (routes, API handlers, database migrations, and configuration). It describes only what is implemented in the codebase — no assumed or planned features are included.

---

## 1. Project Overview

LearnMate AI provides a dashboard-based learning workspace where a signed-in user can:
- Chat with an AI tutor for topic explanations.
- Talk to the AI using their microphone and hear spoken replies (voice tutor).
- Upload PDF study materials, have them indexed, and ask questions answered strictly from those documents (RAG — Retrieval-Augmented Generation).
- Auto-generate multiple-choice quizzes from indexed documents and take them.
- View analytics/performance charts based on their own quiz attempt history.
- Manage their profile and export their account data.
- Switch the UI language between English and Tamil.

The public-facing pages (landing page, features, pricing, reviews) use static/marketing content, while the authenticated `/dashboard/*` area is the functional product.

## 2. Features Actually Implemented

### Core learning features
- **AI Tutor (text chat)** — `/dashboard/tutor`: Sends a question + difficulty level (beginner/intermediate/advanced) to an AI chat model and renders a structured Markdown answer (Explanation, Real World Example, Important Points, Summary).
- **Voice AI Tutor** — `/dashboard/voice`: Uses the browser's **Web Speech API** (`SpeechRecognition`) for speech-to-text (English), sends the transcribed question to the same tutor endpoint, and can play back the AI's answer as speech via a text-to-speech API call. Conversation history is persisted per browser session to the `chat_history` table.
- **Study Materials / PDF RAG** — `/dashboard/materials`: Upload a PDF to Supabase Storage, extract and chunk its text, generate embeddings, store them in a vector column, and answer user questions using only retrieved chunks from that user's session (with citations to document name, page number, and similarity score).
- **Quiz Center** — `/dashboard/quiz`: Generates multiple-choice quizzes (5 / 10 / 20 questions, selectable difficulty and optional topic/document filter) strictly from a session's indexed document chunks. Quiz attempts (answers, score, total) are saved to the database.
- **Analytics** — `/dashboard/analytics`: Reads the current session's real `quiz_attempts` and `quizzes` rows from Supabase and renders charts (score trend, subject/topic breakdown, etc.) computed from that live data — this page does **not** use the static mock dataset.
- **Bilingual UI (English / Tamil)** — a custom i18n dictionary (`src/lib/i18n.tsx`) translates interface labels between `en` and `ta`, persisted via `localStorage`. Note: speech recognition is hardcoded to `en-US`, so voice *input* remains English-only regardless of the selected UI language.
- **Authentication** — Email/password sign-up and sign-in via Supabase Auth (`supabase.auth.signUp` / `signInWithPassword`). No OAuth/social login is implemented.
- **Profile management** — View/edit display name and an avatar URL, backed by a `profiles` table auto-created on signup via a database trigger.
- **Data export** — Settings page lets a signed-in user download a JSON export of their own account data.
- **Theme toggle** — light/dark theme switching component.

### Marketing / static-data pages (not connected to the backend)
- Landing page (`index.tsx`), Features page, Pricing page, and Reviews page use hardcoded/mock content (see "Mock & Static Data" below) for illustrative statistics, testimonials, and sample quiz questions. These are **not** wired to Supabase and do not reflect live data.

### Not implemented
- No payment/checkout integration (the Pricing page has no Stripe/Razorpay or similar payment code; the "Upgrade to Pro" button in the dashboard has no backend action).
- No automated test suite (no test files or test runner are present in the project).
- No OAuth/social login.
- No mobile app — this is a responsive web application only.

## 4. Architecture / Workflow

```
Browser (React SPA/SSR pages)
   │
   ├─ Web Speech API (STT, client-side only)
   │
   ├─ TanStack Router routes (src/routes/*.tsx)
   │      ├─ Public pages: index, features, pricing, reviews, auth
   │      └─ /dashboard/* (protected app shell, src/routes/dashboard.tsx)
   │             ├─ tutor, voice, materials, quiz, analytics, profile, settings
   │
   ├─ Supabase client (browser, anon key) — direct table reads/writes governed by RLS
   │      chat_history, documents, document_chunks, quizzes, quiz_attempts, profiles
   │
   └─ Server API routes (TanStack Start server handlers, src/routes/api/*.ts)
          ├─ POST /api/tutor         → Lovable AI Gateway chat completion (structured answer)
          ├─ POST /api/tts           → ElevenLabs text-to-speech → returns audio/mpeg
          ├─ POST /api/embed-pdf     → downloads PDF from Storage → unpdf text extraction
          │                             → chunking → Lovable AI Gateway embeddings
          │                             → inserts into document_chunks (pgvector)
          ├─ POST /api/ask-pdf       → embeds the question → pgvector similarity search
          │                             (match_document_chunks RPC) → builds context
          │                             → Lovable AI Gateway chat completion with citations
          └─ POST /api/generate-quiz → samples indexed chunks for a session → Lovable AI
                                        Gateway chat completion → JSON quiz → stored in `quizzes`
```

Server routes use a Supabase **service-role** client (`client.server.ts`) to bypass Row Level Security for trusted server-side operations (e.g., writing embeddings), while the browser uses the **publishable/anon** key client, constrained by RLS policies defined in the SQL migrations.

Each browser session is identified by a random UUID (`crypto.randomUUID()`) stored in `localStorage`, used to scope chat history, uploaded documents, quizzes, and quiz attempts — independent of (but compatible with) Supabase Auth user accounts.

## 5. Setup / Install Instructions

**Prerequisites:** Bun (or Node.js) and a Supabase project with the `vector` extension available.

```bash
# 1. Install dependencies
bun install
# (or: npm install)

# 2. Configure environment variables (see section below) in a .env file

# 3. Apply database migrations to your Supabase project
supabase db push
# (or run the SQL files in supabase/migrations/ manually via the Supabase SQL editor)

# 4. Start the development server
bun run dev
# (or: npm run dev)
```

## 7. Database / Supabase Overview

Schema is defined by six SQL migration files under `supabase/migrations/`. All tables have Row Level Security (RLS) **enabled**.

| Table | Purpose | Notable columns |
|---|---|---|
| `chat_history` | Stores voice/text tutor Q&A per session | `session_id`, `question`, `answer`, `level` |
| `documents` | Metadata for uploaded PDF study materials | `session_id`, `file_name`, `file_path`, `file_size`, `status` (`Uploaded`/`Indexing`/`Indexed`/`Failed`/`No text`) |
| `document_chunks` | Chunked PDF text + embeddings for RAG | `document_id`, `session_id`, `page_number`, `chunk_index`, `chunk_text`, `embedding vector(1536)` |
| `quizzes` | AI-generated quizzes | `session_id`, `title`, `num_questions`, `questions` (JSONB) |
| `quiz_attempts` | A user's answers/score for a quiz | `quiz_id`, `session_id`, `answers` (JSONB), `score`, `total` |
| `profiles` | User profile linked to Supabase Auth | `id` (FK to `auth.users`), `display_name`, `avatar_url` |

Additional database objects:
- **`vector` extension** (pgvector) enabled for embedding storage.
- **HNSW index** (`document_chunks_embedding_idx`) on the `embedding` column for fast cosine-similarity search.
- **`match_document_chunks(query_embedding, match_session_id, match_count)`** — a SQL function performing cosine-similarity vector search scoped to a session, used by `/api/ask-pdf`.
- **`handle_new_user()`** trigger — automatically creates a `profiles` row when a new `auth.users` record is created (with backfill for existing users).
- **Storage bucket:** `pdf-documents`, with RLS policies allowing upload/read/delete.
- RLS policies are currently permissive (`anon, authenticated` roles can read/insert most rows scoped by `session_id`), except `profiles`, which is restricted to the owning `auth.uid()`.

## 10. Known Limitations

- No automated test coverage.
- Voice input (speech-to-text) is hardcoded to English (`en-US`); it does not follow the selected UI language (English/Tamil).
- RLS policies on most tables are permissive by `session_id` rather than strict per-authenticated-user ownership, meaning any client that knows/generates a session ID can read/write session-scoped rows (chat history, documents, quizzes). Only `profiles` is fully user-restricted.
- No payment/subscription system is implemented despite a Pricing page and an "Upgrade to Pro" UI element in the dashboard.
- The public landing, features, and reviews pages use hardcoded/mock statistics and testimonials, not real user or usage data.
- No offline mode; all AI, TTS, and vector search features require network access and configured third-party API keys.
- `openai` and `@google/genai` are declared as dependencies but unused in code — they can likely be removed unless intended for future work.
